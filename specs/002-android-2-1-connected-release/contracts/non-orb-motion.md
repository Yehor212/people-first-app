# Non-Orb Motion Contract

> **PRE-RECOVERY INPUT:** retain as historical constraints only. Current motion work must first complete T191–T196, including fresh baselines, 4–6 directions, three variants per named flow and explicit owner artistic selection. The canonical orb remains frozen.

## Scope

`ValenceOrb` and `MiniValenceOrb` are frozen and receive regression-only coverage. This contract governs every other production-reachable animation, beginning with `GratitudeBloomWidget` and `BurnThoughtWidget` (the user-facing Let Go of a Thought effect).

Each effect must have one inventory row: source owner, route/trigger, user-visible meaning, frequency, normal sequence, reduced/runtime-disabled sequence, visible exit, focus/Back owner, timers/RAF/canvas/listeners, layout/compositing risk, supported locales/platforms and evidence status.

## Gratitude Bloom

Normal motion communicates exactly three semantic phases:

1. the entered gratitude is accepted and the input yields;
2. one calm seed-to-stem-to-bloom transformation confirms planting;
3. a stable success message appears before a short non-blocking close.

The effect must not add extra reward pressure, obscure save failure, prevent Back/Close, retain the entered text in evidence/logs, or use particle motion as the only completion cue. Rapid close/background/unmount clears every haptic/validation/close timer. A save failure stays visible and does not animate a false success.

Reduced or runtime-disabled motion calls the same validated save exactly once, renders the success state without travel/scale springs/particle burst/delayed collapse and preserves a visible exit. Opacity-only or instant state replacement is acceptable when it does not delay completion.

## Let Go of a Thought

Normal motion retains the quiet release metaphor: readable pause → compact pressure handoff → text-derived dust → stable text-free release confirmation. Fire, burning, destruction and celebratory reward language remain excluded. The released private text is used only in the transient DOM/canvas effect and is never passed to `onReleased`, logs, diagnostics, storage or captures.

The canvas budget must adapt to measured device/runtime conditions rather than assuming the existing 820/1,180 particles are safe. RAF stops on completion, close, unmount, visibility loss or runtime motion disable; timers and `will-change`/inline transforms are cleared. Canvas/context failure falls directly to truthful semantic completion.

Reduced or runtime-disabled motion skips canvas creation, pressure wave, ambient motes, particles, draw-check animation, scale/translation spring and delayed collapse. It deletes the transient text, invokes the text-free release callback once and immediately exposes the same success/failure meaning plus an exit.

## Navigation, localization, and accessibility

The initiating journal owner retains Escape/Android Back priority over the effect. Close remains at least 48dp on the Android-first route and does not disappear during a long-running sequence unless another always-reachable cancel/finish control owns the same action. Completion is announced once; visual particles/color are never the only signal.

`en`, `uk`, `es`, `de`, `fr`, `ja`, `ar`, `he` are all required at 200% text, narrow portrait, landscape/split and normal/reduced motion. Arabic/Hebrew verify logical positioning, bidi text/counters and direction-aware dust travel without mirroring semantic icons incorrectly.

## Performance and evidence

The release gate reuses the repository's stricter thresholds: representative physical device required, frame-duration CPU P95 and frame-overrun P95 at most 32ms, no reproducible frozen frame over 700ms, and no crash/ANR. Raw frame distribution, display refresh rate, build type, device/thermal/compilation state and capture path are retained for each named effect. Android's 16ms 60Hz guidance informs diagnosis; the repository's 32ms P95 is the release rejection line, not a promise that every frame may take 32ms.

Evidence layers remain separate:

- `Technical`: tests, cleanup, semantic state and artifact checks;
- `Visual Runtime`: direct normal/reduced captures on the claimed build/device;
- `Artistic/Craft`: qualified human review only;
- `Motion`: measured frame/timing and comfort evidence;
- `Model`: N/A because these effects use DOM/SVG/canvas, not a 3D/model asset;
- `Plan`: Spec Kit traceability and open gates.

A browser/component run, software-GPU emulator trace or code review cannot become physical-device or human-eye `PASS`. Any missing layer stays `UNVERIFIED`; a measured threshold breach is `FAIL`.
