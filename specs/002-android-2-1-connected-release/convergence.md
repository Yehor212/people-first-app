The applicable source boundary is narrow:

- WCAG 2.2 Reflow requires information and functionality to remain available
  at a 320 CSS-pixel equivalent. Unlike ZenFlow's seven-column calendars, this
  current/next schedule summary is linear content, so an internal horizontal
  data scroller would add navigation burden without preserving a necessary
  two-dimensional relationship. The accepted behavior is natural vertical
  reflow inside the existing action.
  <https://www.w3.org/WAI/WCAG22/Understanding/reflow.html>
- W3C's Focus Visible guidance applies because the whole summary is one
  keyboard action. The fix retains one button and adds a token-based visible
  focus boundary instead of splitting the card into competing controls.
  <https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html>
- Android recommends touch targets of at least 48dp. The final Web matrix has a
  66px minimum action dimension, and the API-36 Hebrew/200% component capture
  measures a 341.52px-high action; no text or target was shrunk to keep the
  original compact height.
  <https://developer.android.com/guide/topics/ui/accessibility/views/apps-views>

The implementation changes only `GlobalScheduleBar`: it uses its own container
width to keep clock and chevron in the first row while moving the schedule
summary to a full-width second row when constrained. Event titles use natural
word wrapping, long user-authored tokens may break only as the last-resort
`overflow-wrap:anywhere` boundary, and `now`/time-until metadata moves below the
title before it can squeeze words into character columns. At wider component
widths the existing one-row hierarchy returns. The accepted tradeoff is a
taller action under narrow or 200% text conditions; a permanently compact card,
ellipsis, page-level horizontal scrolling, reduced text, hidden chevron or a
bulk schedule redesign are rejection conditions.
