# Contract: Disposable Local Schema Replay and Type Generation

**Contract version**: 1
**Selected by**: T167
**Execution owner**: T169, only after T168 migration admission and a new exact source binding
**T167 execution state**: `DEFERRED`; both commands below are `NOT_EXECUTED`

## Purpose

This contract defines the only selected future path for rebuilding the reviewed ZenFlow Supabase schema and generating TypeScript declarations. It does not authorize execution, migration admission, dependency installation, remote access, type-file modification, or Git publication.

## Preconditions

Every precondition must be freshly verified in the future execution lane:

1. T168 has completed its bounded semantic, RLS/RPC, privacy, rollback, and admission review for the exact automation migration bytes.
2. Every admitted migration and `supabase/config.toml` is tracked and clean in the authorized lane; no migration is untracked, staged differently, modified, deleted, conflicted, or symlinked.
3. Index bytes, working-tree bytes, and expected reviewed bytes match for every admitted input.
4. The complete sorted migration inventory, count, Git tree, per-file byte/hash bindings, and canonical aggregate SHA-256 have been recomputed after T168.
5. The dirty-umbrella journal privacy migration remains outside the set unless a separately authorized task admits it.
6. The target is a fresh disposable local Supabase instance. No hosted project identifier or linked remote target is selected.
7. Supabase CLI and Docker availability, versions, provenance, and local daemon health have been verified without weakening repository policy or installing unapproved dependencies.
8. No production or user-derived seed is selected. Seed execution is disabled.
9. The executing task explicitly authorizes replay and regeneration and defines retained logs, rollback, and diff verification.

Failure or absence of any precondition is a stop. A stale T167 digest must not be reused after source admission.

## Ordered Future Commands

The future executor must run exactly these two source-selection commands in order from the authorized repository root:

```sh
supabase db reset --local --no-seed
supabase gen types typescript --local
```

The first command must complete successfully before the second begins. T167 records these strings for auditability and does not invoke either command, any alias, or any equivalent API.

## Required Future Evidence

### Local replay

- exact execution lane identity and newly reviewed migration inventory;
- CLI and Docker versions/provenance;
- proof the target is local and disposable, not linked or remote;
- command, start/end timestamps, exit code, and retained stdout/stderr location with secrets excluded;
- proof seed execution remained disabled;
- applied migration order and failure/rollback behavior;
- zero production data or external writes.

### Type generation

- command, timestamps, exit code, and source target `--local`;
- generated byte count and SHA-256;
- exact diff limited to the authorized type target and evidence artifacts;
- semantic checks against the replayed schema plus the repository freshness guard;
- downstream typecheck/tests and cross-platform impact review;
- no hand edits, mock data, secrets, customer data, or remote metadata.

## Prohibited Variants

- `supabase db reset` without both `--local` and `--no-seed`;
- generation with a project ID, linked project, hosted database URL, access token, or other remote selector;
- replay from the dirty umbrella or from a mixed tracked/untracked set;
- manual edits presented as generated declarations;
- use of timestamps as semantic-equivalence proof;
- installing tools or dependencies without separate authorization;
- running either command in T167 or T168;
- committing, pushing, opening a PR, merging, deploying, or publishing as an implied consequence of local generation.

## Failure Handling

On replay failure, stop before generation and preserve non-secret local diagnostics. Discard the disposable local instance; do not repair hosted state. On generation or validation failure, keep the generated target uncommitted, report `FAIL`, and restore only task-owned local output through an explicitly reviewed rollback. Never adjust tests, policies, migration order, source membership, or evidence criteria merely to obtain a green result.
