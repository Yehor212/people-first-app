# Offline Editor Build Contract

`createDiaryOfflinePrecache({ root })` returns a Vite `plugin` and Workbox `manifestTransform`. The plugin is build-only, post-enforced, resets its collected state at buildStart and resolves JournalEntryEditor and JournalEntryList by their source module identities in the emitted bundle. Both are required for the first offline save and subsequent list reload. It follows static chunk imports and each chunk's emitted CSS/assets, deduplicates cycles, and rejects an absent required root or any unresolved edge. Optional dynamic feature imports are not included.

Collection runs at writeBundle, after Vite's generateBundle preload-list rewrites, so revision bytes match files on disk. The plugin also resolves the emitted initial-entry static graph and rejects missing boot edges or an editor that has become eager. Shared boot dependencies stay on the existing visited-route caching path; only the editor dependency set minus that boot set is added to precache. This contract requires the existing controlled online boot/Diary visit before disconnecting and does not expand offline availability to an unvisited shell. Both dependency sets are metadata-derived, not a hardcoded exemption list.

Each collected entry is `{ url, revision, size }`, with a relative emitted assets path, the Workbox-compatible MD5 content identifier of actual emitted bytes and byte length. This revision is a cache identifier, never a password hash or security/trust digest. The existing Pages release seal independently retains SHA-256 for all artifact bytes. Each emitted resource must be at most 3145728 bytes. The manifest transform requires completed collection, preserves original manifest entries/revisions, adds only missing URLs, and rejects a total added size above 655360 bytes. Fresh object copies prevent Workbox's size-removal step from mutating retained collector state across repeated transforms.

The existing pwaEnabled condition owns both registration of the build collector and use of its transform. Capacitor and explicitly disabled-worker builds must not invoke it. Existing service-worker update/cleanup/cache keys and IndexedDB records remain unchanged. An installed update may require connectivity before offline readiness; eviction is not represented as supported offline installation.

The measured final graph is 566129 bytes including the existing dark-theme image. Exact-limit acceptance and one-byte-over rejection are tested before implementation; the image, other dependency bytes and per-file guard remain unchanged. Fresh build and runtime evidence are still required.

The cache identifier format follows the actual `computeWorkboxRevision`/`verifyServiceWorkerPrecacheReferences` release contract and installed Workbox implementation. A cross-boundary regression must pass the unchanged release verifier with real emitted fixture files, then reject a changed editor file. Production acceptance includes Pages preparation, staging and the staged artifact check, not only raw Vite build success.
