# Adaptive evidence-first agent router

> Status: owner-approved candidate implementation. Structural behavior can be
> verified locally; whole-run token savings and quality superiority remain
> `UNVERIFIED` until paired real-task evaluation.

## Outcome

Keep exactly ten stable ZenFlow roles, consider every role on every substantive
route, and physically invoke only the smallest evidence-required set. Expand Role 2
for concrete agency, pressure, interruption, recovery, consent, sensitive-copy, and
bounded clinical-product risks. Do not activate it from a generic feature name.

## Abstract-request algorithm

1. The root task runs scoped RAG and local repository discovery before specialist
   selection. It resolves the exact route, symbol, state, interaction, copy,
   platform, data flow, current failure evidence, and unknowns.
   The manifest binds the request, locators, resolved scope, discovery commands, and
   every platform/domain row into a verified discovery receipt.
2. It maps only observed evidence to canonical trigger IDs. Missing evidence remains
   `UNVERIFIED`; unresolved protected ambiguity uses `MATERIAL_AMBIGUITY`.
3. It records all ten roles in canonical order as `SELECTED` or `EXCLUDED`, with
   a reason and at least one direct evidence locator for every decision.
4. M0 runs deterministic QA. M1 runs matched owners plus QA. M2 adds Role 10 Pass A
   and Pass B. Selected domain owners receive initial/final review; selected Role 2
   receives `CREATE_BRIEF` and `INDEPENDENT_FINAL_REVIEW`.
5. `DEEP_AUDIT` explicitly selects all ten. For M1/M2, `FIXED_FULL_TEN` retains
   the legacy exact 20-phase plan as a reviewable rollback; M0 stays deterministic.
6. Any missing mandatory owner, consideration entry, evidence locator, receipt,
   dependency, platform/domain row, or measured promotion counter fails closed.
7. Promotion also requires a separately authenticated discovery receipt and paired,
   hash-bound baseline/candidate ledgers with matched execution conditions and at
   least 5 percent recomputed total-token reduction.

## Scope and boundaries

- Writes: canonical orchestra registry, assurance/registry validators, structural
  evals, generated profiles/reference, and agent-governance documentation.
- No writes: product runtime, IndexedDB, Zustand, Supabase, sync, auth, analytics,
  native projects, public deployment, or production data.
- No mock/demo/sample product or user data. Malformed schema objects remain allowed
  only as isolated validator negative controls and never represent product evidence.
- Role 2 cannot prove actual feelings, diagnosis, treatment, clinical safety,
  accessibility conformance, cultural acceptance, or product acceptance.

## Acceptance and rejection

- PASS structural routing only when focused RED becomes GREEN, exactly ten roles
  remain registered, generated artifacts match, vague Settings discovery does not
  select Role 2 by keyword, concrete human-factor risk does select Role 2, M2 adds
  Role 10, deep audit selects all ten, and rollback retains 20 phases.
- Reject adaptive routing if any protected positive control omits its owner, any
  mechanical negative control selects an unrelated owner, or all-ten consideration
  lacks evidence locators.
- Do not claim lower total Codex tokens or equal/better quality until same-model,
  same-reasoning, same-tool paired runs on privacy-scrubbed real ZenFlow tasks record
  exposed input, cached/cache-write, output, reasoning, latency, retry, and reviewer
  effort fields with zero new critical misses and a preregistered noninferiority
  margin.

## Rollback

Set an M1/M2 run routing mode to `FIXED_FULL_TEN` for immediate behavioral rollback.
A repository rollback reverts the adaptive registry/core/tests/docs together and
regenerates managed profiles. No migration, production record, external write,
commit, push, or deploy is required.
