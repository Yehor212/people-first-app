# ZenFlow Brand Logo Contract

Purpose: keep the ZenFlow mark consistent across web, PWA, native splash screens,
desktop EXE, Microsoft Store assets, and future release work.

## Non-Negotiables

- The logo mark is the approved classic ZenFlow leaf vector generated by
  `scripts/generate-icons.cjs` and `scripts/generate-microsoft-store-logo-assets.cjs`.
- Do not replace it with exploratory logo concepts, stock leaf icons,
  SVG-filter glow marks, static screenshots, or AI-generated one-off raster art.
- Do not add SVG filters, `feDropShadow`, or rasterized shader effects to logo
  source SVGs. They can produce square glow artifacts on Store, Android, iOS,
  Windows, and compressed preview surfaces.
- All app/platform/store logo files must be regenerated from the scripts, then
  validated with `npm run assets:logos:check`.
- Runtime splash logo and generated image assets must use the same classic
  vector silhouette. The splash screen may change scale, shadow, or surrounding
  background only when the mark stays identical.
- Public static pages (`404.html`, offline, privacy, terms, delete-account)
  must expose the same canonical favicon, 192px PWA icon, Apple touch icon, and
  share image as the main app. The offline screen and placeholder fallback must
  display the ZenFlow leaf, never a browser/file-type icon, emoji, or gray
  template placeholder.

## Quality Bar

- The mark must remain readable at tiny sizes: favicon, taskbar, Android
  launcher, Windows tile, and small Store cards.
- The mark must have enough contrast against the emerald plate and dark splash
  background without relying on blur or glow.
- Small raster surfaces must prefer clean leaf edges over decorative depth:
  inner detail shadow is allowed only when the rendered mark is large enough to
  stay crisp after platform compression and scaling.
- The large Store artwork may use richer composition, but the core mark must
  still be centered, quiet, and immediately recognizable.
- Use simple geometry, clear whitespace, and platform safe areas rather than
  decorative detail that disappears at small sizes.
- Representative favicon, Windows, Android, PWA, and Store icons must keep the
  white leaf inside a measurable safe zone. The logo guard checks this by
  finding the visible white mark in key raster outputs.
- Store square and poster artwork must keep a measured clear-space gap between
  the icon plate and the `ZenFlow` wordmark. Text must never touch, overlap, or
  visually crowd the app tile in Partner Center previews.
- Golden-ratio proportions may guide the large artwork grid, but they are not a
  substitute for platform rules. Official safe areas, Store overlay behavior,
  small-size readability, and optical clear-space win over a decorative ratio.
- Splash/loading screens must use the same classic leaf silhouette and keep the
  app name visually separated from the icon. If the icon scale changes, verify
  the text gap on the runtime splash, native splash, and generated Store art.
- Logo proof sheets must not upscale tiny platform rasters as if they were
  hero artwork. Files such as 32px Tauri icons, 48px Android mdpi icons, and
  50px Windows StoreLogo are judged at native size plus a capped pixel-audit
  preview, while large PWA, splash, and Store assets are judged as high-density
  surfaces.

## Required Evidence

Before claiming logo work complete:

- `npm run assets:logos:check`
- `npm run check:visual`
- splash/loading focused tests when runtime splash was touched
- contact sheet proof covering favicon, PWA, Android, iOS, Tauri, splash, and
  Microsoft Store surfaces
- `npm run assets:logos:proof` for an honest proof sheet that separates tiny
  native rasters from high-resolution marketing surfaces
- static public-page proof from `npm run assets:logos:check`, including
  favicon/PWA/apple links and the branded `public/placeholder.svg`
- security scan for any changed script/runtime code
