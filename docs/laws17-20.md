# Laws 17-20 — Extended Constitution

## Law 17 — INTERNATIONALIZATION & CULTURAL INTEGRITY (THE BABEL LAW)

> "If one user in one language sees broken text, the app is broken for 12.5% of the world."

### Core Principle

The app serves 8 languages (en, uk, es, de, fr, ja, ar, he) including 2 RTL (ar, he). You are STRICTLY FORBIDDEN from introducing ANY user-facing string without an i18n translation key. Every UI element must be culturally and directionally correct across ALL supported locales.

### Rules

**RULE 1 — NO HARDCODED STRINGS**: Every user-visible string MUST use `t.keyName` with a fallback `|| 'English default'`. FORBIDDEN: raw English strings in JSX without translation keys. Before adding ANY text to UI, verify the key exists in `src/i18n/translations.ts` (or add it to ALL 8 language files).

**RULE 2 — RTL DIRECTIONAL INTEGRITY**:
- ALL directional icons (`ChevronRight`, `ChevronLeft`, arrows, `>`, `<`) MUST have `rtl:scale-x-[-1]` class.
- FORBIDDEN: `text-left`/`text-right`, `ml-`/`mr-`, `pl-`/`pr-`, `left-`/`right-`. Use CSS logical properties: `text-start`/`text-end`, `ms-`/`me-`/`ps-`/`pe-`, `start-`/`end-`.
- FORBIDDEN: `float-left`/`float-right`. Use `float-start`/`float-end`.
- FORBIDDEN: `border-l-`/`border-r-`. Use `border-s-`/`border-e-`.

**RULE 3 — PLURALIZATION & FORMATTING**:
- Numbers must use locale-aware formatting (`.toLocaleDateString(locale)`, `Intl.NumberFormat`).
- FORBIDDEN: string concatenation for plurals (`count + " items"`). Use interpolation with translation keys that handle plural forms.
- Date displays must respect locale ordering (MM/DD vs DD/MM vs YYYY/MM/DD).

**RULE 4 — TEXT EXPANSION**:
- German text is typically 30% longer than English. Japanese may be shorter. Layouts MUST accommodate text expansion without overflow, truncation, or layout breakage.
- FORBIDDEN: fixed-width containers for translated text. Use `min-w-0` + `truncate`/`line-clamp` as safety nets.

**RULE 5 — FALLBACK AUDIT**:
- Every `t.key || 'Fallback'` must have the SAME semantic meaning as the actual translations.
- FORBIDDEN: fallbacks that contradict or diverge from the translated strings.

**RULE 6 — RTL VISUAL VERIFICATION**:
Logical properties alone do NOT guarantee correct RTL layout. Arabic and Hebrew are supported languages — visual verification is non-negotiable.

- After any layout/spacing change, visually verify Arabic or Hebrew rendering
- Quick check: browser DevTools → `document.dir = 'rtl'` on `<html>` element
- Verify: text alignment, icon direction, navigation flow, form label positions
- FORBIDDEN: assuming `ms-`/`me-`/`ps-`/`pe-` is sufficient without visual confirmation
- Focus areas: navigation bar, modal headers, form layouts, list items, tooltips

**Why**: Logical properties handle MOST RTL correctly, but edge cases exist: absolute positioning (`left:`/`right:` not auto-converted), Canvas/SVG text rendering, animation slide directions (`translateX` needs sign flip), toast/notification positions, and scroll behavior.

### Anti-Pattern Examples

```tsx
// BAD: hardcoded English
<p>No entries yet</p>

// GOOD: translation with fallback
<p>{t.noEntriesYet || 'No entries yet'}</p>

// BAD: physical direction
<div className="ml-4 text-left border-l-2">
<ChevronRight className="w-4 h-4" />

// GOOD: logical direction + RTL flip
<div className="ms-4 text-start border-s-2">
<ChevronRight className="w-4 h-4 rtl:scale-x-[-1]" />
// Note: Visual-only flip. For semantic direction, prefer directional icon variants when available.

// BAD: absolute position without RTL consideration
<div className="absolute left-4 top-0">

// GOOD: logical positioning
<div className="absolute start-4 top-0">
```

### Evidence Requirement
For every new UI string: "Translation key: `t.keyName`. Present in all 8 languages: YES/NO. RTL-safe: YES/NO."
For layout changes: "RTL visual check performed: YES/NO. Method: [DevTools dir=rtl / Arabic test]."

## Law 18 — RESOURCE LIFECYCLE & CLEANUP (THE HOUSEKEEPING LAW)

> "Every resource you acquire, you must release. Every listener you add, you must remove. No exceptions."

### Core Principle

With hundreds of timer/listener registrations across the codebase, resource leaks are a constant threat. You are STRICTLY FORBIDDEN from registering any event listener, timer, subscription, or observer without a corresponding cleanup path. React's Strict Mode double-invokes effects — your code MUST survive this.

### Rules

**RULE 1 — EFFECT CLEANUP MANDATE**: Every `useEffect` that registers a side effect MUST return a cleanup function. No exceptions.
```tsx
// FORBIDDEN
useEffect(() => {
  window.addEventListener('resize', handler);
}, []);

// MANDATORY
useEffect(() => {
  window.addEventListener('resize', handler);
  return () => window.removeEventListener('resize', handler);
}, []);
```

**RULE 2 — TIMER CLEANUP**: Every `setTimeout`/`setInterval` MUST store the ID in a ref and clear it on cleanup.
```tsx
// FORBIDDEN
useEffect(() => {
  setTimeout(() => doSomething(), 1000);
}, []);

// MANDATORY
useEffect(() => {
  const timer = setTimeout(() => doSomething(), 1000);
  return () => clearTimeout(timer);
}, []);
```

**RULE 3 — SUBSCRIPTION CLEANUP**: Every Supabase subscription, WebSocket, or event emitter MUST be unsubscribed on unmount.
```tsx
// MANDATORY pattern
useEffect(() => {
  const { data: subscription } = supabase.auth.onAuthStateChange(callback);
  return () => subscription?.subscription?.unsubscribe?.();
}, []);
```

**RULE 4 — MOUNT GUARD**: Async operations that set state MUST check if the component is still mounted.
```tsx
useEffect(() => {
  let mounted = true;
  fetchData().then(data => {
    if (mounted) setState(data);
  });
  return () => { mounted = false; };
}, []);
```

**RULE 5 — STRICT MODE RESILIENCE**: Code MUST work correctly when effects fire twice (React 18 Strict Mode). Idempotent setup/teardown.

**RULE 6 — DOM MUTATION CLEANUP**: Any direct DOM manipulation (`document.body.style`, `classList.add`, attribute changes) MUST be reversed on cleanup. FORBIDDEN: leaving orphaned styles/classes on `document.body`.

### Anti-Pattern: The iPhone Touch-Death Bug
`useScrollLock` modified `document.body.style` in a `useEffect`. When two components both locked, the child's cleanup restored styles to the pre-parent state, leaving `body` in a broken state. **Fix**: Reference-counted global lock/unlock.

### Evidence Requirement
For every `useEffect` with side effects: "Side effect: [description]. Cleanup: [description]. Strict Mode safe: YES/NO."

## Law 19 — TEMPORAL INTEGRITY (THE CLOCK LAW)

> "Time is the most deceptive variable. new Date() is a lie — it changes every millisecond."

### Core Principle

With 171 raw `new Date()` calls and time-sensitive features (streaks, daily habits, mood tracking, focus sessions), temporal bugs are silent killers. You are STRICTLY FORBIDDEN from using raw `new Date()` for date comparisons or "today" checks. The app has a canonical `getToday()` utility — USE IT.

### Rules

**RULE 1 — CANONICAL TODAY**: For "today" date strings, ALWAYS use `getToday()` from `@/lib/utils`. For parsing existing date strings, use `parseLocalDate()` from the same module to avoid UTC timezone traps. FORBIDDEN: `new Date().toISOString().split('T')[0]` or any ad-hoc today calculation.

**RULE 2 — DATE COMPARISON SAFETY**:
- Date strings MUST be compared as strings in `YYYY-MM-DD` format (ISO 8601).
- FORBIDDEN: comparing `Date` objects directly (`date1 > date2`) — timezone offsets cause subtle bugs.
- FORBIDDEN: `Date.parse()` for user-facing date strings without explicit timezone handling.

**RULE 3 — TIMEZONE AWARENESS**:
- The user's timezone is stored in their profile (`profiles.timezone`).
- `getToday()` returns the date in the user's LOCAL timezone, not UTC.
- FORBIDDEN: using UTC dates for daily habit entries, streak calculations, or mood logging.
- All "day boundary" logic (midnight rollover, streak reset) must use local timezone.

**RULE 4 — TEMPORAL IMPOSSIBILITY CHECK**:
- Users CANNOT complete habits in the future.
- Users CANNOT log mood for past dates (only today).
- Timers CANNOT show negative values.
- Streak counts CANNOT be negative.
- Timestamps MUST be monotonically increasing within a session.

**RULE 5 — MIDNIGHT ROLLOVER**:
- When the app is open at midnight, date-dependent UI must update.
- `useDateTracking` hook exists for this — verify it's used where needed.
- FORBIDDEN: caching `getToday()` in a `const` at module level (becomes stale at midnight).
```tsx
// FORBIDDEN: module-level cache (stale after midnight)
const TODAY = getToday(); // Computed once at import time — never refreshes
export function isToday(date: string) { return date === TODAY; } // BUG at midnight

// MANDATORY: per-invocation call
export function isToday(date: string) { return date === getToday(); } // Always fresh
```

**RULE 6 — DURATION FORMATTING**:
- Timer display: `MM:SS` format (e.g., `02:30`) — used by `formatTime()` in `@/lib/utils`.
- Summary/total display: `Xh Ym` format (e.g., `2h 30m`) for values >60 minutes.
- FORBIDDEN: showing raw "150 minutes" when "2h 30m" is clearer.

### Anti-Pattern Examples
```tsx
// BAD: raw Date for "today" — timezone-unsafe
const today = new Date().toISOString().split('T')[0]; // UTC date, not local!

// GOOD: canonical utility
const today = getToday(); // Returns local date

// BAD: Date object comparison
if (new Date(entry.date) > new Date(otherDate)) // Timezone trap

// GOOD: string comparison for date-only values
if (entry.date > otherDate) // YYYY-MM-DD string compare is safe
```

### Evidence Requirement
For every time-related operation: "Date source: `getToday()` / `Date.now()` / raw `new Date()`. Timezone-safe: YES/NO. Midnight-rollover handled: YES/N/A."

## Law 20 — COPY & MICROCOPY INTEGRITY (THE VOICE LAW)

> "Every word the user reads is part of the product. 'undefined' is a critical bug."

### Core Principle

User-facing text is not an afterthought — it IS the interface. You are STRICTLY FORBIDDEN from allowing `undefined`, `null`, `NaN`, `[object Object]`, or raw error messages to appear in the UI. Every text element must be meaningful, actionable, and human.

### Rules

**RULE 1 — NO UNDEFINED/NULL IN UI**:
- Every dynamic value rendered in JSX MUST have a fallback.
- FORBIDDEN: `{user.name}` without null check. Use `{user.name || 'Friend'}`.
- FORBIDDEN: `{count}` where count might be `undefined`. Use `{count ?? 0}`.
- Template literals with variables MUST guard against undefined: `{t.greeting?.replace('{name}', userName) || `Hello, ${userName}`}`.

**RULE 2 — ERROR MESSAGES ARE UI**:
- Error messages must be written for the USER, not the developer.
- FORBIDDEN: `"Error: SQLITE_CONSTRAINT"`, `"Network request failed"`, `"TypeError: cannot read property"`.
- MANDATORY: Human-readable messages — "Could not save. Please try again.", "Check your connection and retry."
- Technical details go to `logger.error()`, human text goes to UI.

**RULE 3 — EMPTY STATES ARE DESIGNED**:
- Every list, feed, or data display MUST have a designed empty state.
- FORBIDDEN: blank white space when data is empty.
- MANDATORY: illustration/icon + explanatory text + call-to-action when relevant.
- Example: Empty habit list shows "No habits yet. Tap + to create your first one."

**RULE 4 — LOADING STATES ARE INFORMATIVE**:
- Skeleton screens MUST match the shape of the loaded content.
- FORBIDDEN: generic spinner for more than 1 second without explanation.
- For operations > 3 seconds: show progress or "This may take a moment..."

**RULE 5 — BUTTON LABELS ARE ACTIONABLE**:
- FORBIDDEN: "OK", "Yes", "No" for destructive actions.
- MANDATORY: "Delete all data", "Keep data", "Sign out" — labels that describe the ACTION, not confirm the question.
- Delete confirmations must name WHAT is being deleted.

**RULE 6 — NUMERIC DISPLAY CONSISTENCY**:
- Percentages: always show `%` suffix, round to integer unless decimal precision matters.
- Counts: use `0` not empty string when count is zero.
- Durations: "2h 30m" not "150 min" for values > 60.
- Streaks: "3-day streak" not "3" without context.

**RULE 7 — TRUNCATION WITH RESPECT**:
- Long text MUST be truncated gracefully with `line-clamp-N` or `truncate`.
- FORBIDDEN: text overflowing container bounds.
- FORBIDDEN: truncating in the middle of a word without ellipsis.
- If truncated text is important, provide a way to see the full text (expand, tooltip, detail view).

### Anti-Pattern Examples
```tsx
// BAD: undefined leak
<p>{entry.note}</p> // Shows "undefined" if note is missing

// GOOD: guarded render
{entry.note && <p>{entry.note}</p>}

// BAD: developer error message
<p className="text-destructive">{error.message}</p>

// GOOD: human error message
<p className="text-destructive">{t.saveFailed || 'Could not save. Please try again.'}</p>

// BAD: vague button
<button>OK</button>

// GOOD: actionable button
<button>{t.deleteAllData || 'Delete all data'}</button>
```

### Evidence Requirement
For every dynamic text element: "Value source: [state/prop]. Can be undefined: YES/NO. Fallback: [value]. Human-readable: YES/NO."
